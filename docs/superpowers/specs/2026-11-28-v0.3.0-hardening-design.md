# v0.3.0 local hardening design

**Goal:** close the remaining low-risk correctness and documentation gaps from the v0.3.0 review without changing the public feature set, version, or release state.

**Scope:** four narrowly scoped fixes, all local to `feature-v0.3.0`:

1. Reject `ring_lines == 0` instead of silently substituting the 500-line default.
2. Include the accepted alias `warning` in the invalid `min_level` diagnostic.
3. Do not read piped stdin for `logcut test` when `--raw-text` is supplied.
4. Align docs with implemented behavior: watch detection/case notes, `where` value case sensitivity, and lossy UTF-8 decoding of watched output.

**Non-goals:**

- No version bump, tag, merge, push, release, or publish.
- No new MCP `watch` tool; MCP only exposes `get_last_crash` and unchanged `slice_log`.
- No change to the intended case-sensitive matching of bare `where level=error`.
- No change to the severity heuristic that treats untrusted log levels as INFO; only caller-supplied `min_level` is strict.
- No new failure-path test for `write_file_atomically`; its existing cleanup logic is already covered for the success path and is unchanged.

**Constraints:** validation stays in `src/core/` so CLI, MCP, and direct core callers agree; `stdout` remains reserved for JSON-RPC in MCP mode and for reports in CLI mode; `core/` stays free of UI/network coupling; all verification gates must pass with zero warnings.

**Verification:** each behavioral fix gets a RED→GREEN test cycle, followed by `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --all-features`, `cargo check --no-default-features --features mcp`, and `git diff --check`.
