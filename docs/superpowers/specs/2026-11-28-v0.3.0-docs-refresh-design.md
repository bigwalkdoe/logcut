# v0.3.0 documentation refresh design

**Goal:** make every shipped document describe the released `v0.3.0` behavior, with no stale v0.2-era version claims, tool counts, module lists, or release links.

**Approach:** audit README, SPEC, usage, MCP, architecture, troubleshooting, and the docs index; update only statements contradicted by the released code or by the v0.3.0 changelog. Keep the existing document structure and voice. Add short, concrete notes for the new validation rules, NDJSON filters, `test`/`watch` behavior, and the six MCP tools versus four agent tools.

**Non-goals:** no product behavior changes, no version bump, no new release, no restructuring of the docs tree, and no edits to historical superpowers plans/specs that intentionally describe earlier states.

**Verification:** all local relative Markdown links resolve; stale-release and stale-tool-count searches are clean outside historical records; `cargo fmt --all -- --check`, `cargo clippy --all-targets --all-features -- -D warnings`, `cargo test --all-features`, `cargo check --no-default-features --features mcp`, and `git diff --check` pass; changes are committed and pushed to `origin/main`.
