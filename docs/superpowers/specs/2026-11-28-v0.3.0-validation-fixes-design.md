# v0.3.0 validation fixes design

**Intent:** close the three deferred minors from the v0.3.0 final review so invalid inputs fail loudly and both `.logcut` files get the same atomic-write guarantee.

**Goals**
- Reject unknown `min_level` values instead of silently treating them as `info`.
- Reject malformed `where_filters` instead of treating them as no-ops.
- Write `.logcut/.gitignore` through the same temp-file+rename helper used for `last-crash.md`.

**Non-goals**
- No new CLI flags, MCP tools, or output schema changes.
- No change to the documented NDJSON detection threshold or breadcrumb behavior.
- No tag, push, merge, release, or publish.

**Constraints**
- Keep validation in `src/core/` so CLI, MCP, and direct library callers all behave the same.
- Preserve `severity()`’s existing default-to-info behavior for untrusted log *levels*; only the caller-supplied `min_level` becomes strict.
- Keep all output redacted and bounded; keep stdout reserved for reports/JSON-RPC.

**Approaches considered**
1. Validate in the CLI only with strict clap values. Smallest diff, but MCP and direct core callers still accept bad input silently. Rejected.
2. Validate in core by changing `json_log::slice` to return `anyhow::Result<Vec<JsonLogEntry>>` and checking every filter up front. Chosen: one fix covers every transport. Cost is an internal signature change and updates to core callers/tests; v0.3.0 is local and unpublished, so there is no compatibility break.

**Chosen design**
- Add a strict private level parser used by both `severity()` and `slice()`. `severity()` keeps defaulting unknown log levels to `INFO`; `slice()` bails with an actionable error when `min_level` is not `trace|debug|info|warn|error|fatal`.
- Tighten `parse_filter()` so both field and value must be non-empty, then validate every filter in `slice()` before processing any line. Invalid filters bail with the offending filter and the supported operators.
- Extract `write_file_atomically(destination, text)` from `watch::write_atomically()`, create `.logcut` once, and call the helper for both `.gitignore` and `last-crash.md`. Temp files stay unique, are removed on failure, and are renamed into place on success.

**What remains to the implementer**
- Write failing tests for strict level validation, strict filter validation, and the shared atomic writer; implement the smallest code to pass; run fmt, clippy, full tests, and the MCP-only build; commit on `feature-v0.3.0` without publishing.
