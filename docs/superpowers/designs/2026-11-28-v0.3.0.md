# logcut v0.3.0 design

**Goal:** add structured NDJSON log slicing, test-output slicing, and a live crash watcher without changing the existing pure-core/transport boundary.

## Decisions

- `slice_log` auto-detects NDJSON when at least half of the non-empty lines are JSON objects carrying `level` or `message`. NDJSON input is rendered from normalized fields instead of raw lines, so `pid`, `hostname`, and `v` never appear in reports.
- `SliceLogRequest` gains `min_level` (`trace|debug|info|warn|error|fatal`) and repeatable `where_filters` (`field>=number`, `field=value`, with `=`, `!=`, `>`, `>=`, `<`, `<=`). Filters apply to parsed fields; all emitted strings pass through `redactor::redact`.
- For each selected `ERROR`/`FATAL` entry with `trace_id` or `request_id`, up to five earlier `INFO`/`WARN` entries with the same ID are attached as breadcrumbs.
- `slice_test` strips passing-test lines from cargo/pytest/jest/vitest/go output, keeps failing summaries and assertion diffs, maps `file:line` references through `source_ctx`, and returns a `SliceTestReport`.
- `logcut watch -- <COMMAND...>` streams child stdout/stderr, keeps a 500-line ring buffer, slices on a detected panic/traceback/`ERROR` line or non-zero exit, and atomically writes `.logcut/last-crash.md` plus `.logcut/.gitignore` containing `*`.
- MCP adds `slice_test` and `get_last_crash` (reads the stored crash file). MCP stdout stays JSON-RPC-only; `--stats` stays on stderr.

## Non-goals

- No network calls or UI dependencies in `src/core/`.
- No tag, release, publish, push, or merge as part of this work.
- No changes to the published v0.2.0 crate.
