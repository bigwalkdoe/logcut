# logcut v0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship NDJSON-aware `slice_log`, test-output slicing, and crash watching behind the same pure core used by CLI and MCP.

**Architecture:** Three new core modules (`json_log`, `test_runner`, `watch`) implement independent algorithms; `models.rs` owns all typed contracts with `JsonSchema`; `core/mod.rs` composes them with the existing redactor/source-context helpers; CLI and MCP are thin adapters.

**Tech Stack:** Rust 2024, `serde`/`serde_json`, `schemars`, `regex`, `tokio::process`, `clap`, `rmcp`.

**Spec:** `docs/superpowers/designs/2026-11-28-v0.3.0.md`

## Global Constraints

- Keep `src/core/` free of CLI, MCP, and HTTP dependencies.
- All MCP tool parameter structs derive `schemars::JsonSchema`.
- MCP stdout carries JSON-RPC only; `--stats` writes to stderr.
- Redact secrets by default; never emit `pid`, `hostname`, or `v` from NDJSON.
- Bounded/tail reads only; no whole-file buffering for large logs.
- Bump `Cargo.toml` to `0.3.0`; run `cargo fmt --all` and `cargo test` with zero warnings.
- Do not tag, release, publish, push, or merge.

## Review Focus

- Mixed JSON/plain log lines must not be misdetected as NDJSON → `json_log::is_ndjson` needs a mixed-line test.
- `where_filters` numeric comparisons on string fields (`status>=500`) → filter test with boundary values.
- Passing lines with ANSI codes or Go's `ok  \tpkg` form must still be stripped → test runner test.
- Watch must not create `.logcut/last-crash.md` on a successful command → watch test for zero exit.
- Crash report writes must be atomic and `.gitignore` must contain `*` → watch test for directory contents.
