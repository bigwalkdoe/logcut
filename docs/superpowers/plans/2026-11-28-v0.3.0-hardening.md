# v0.3.0 local hardening implementation plan

**Spec:** `docs/superpowers/specs/2026-11-28-v0.3.0-hardening-design.md`

**Execution:** inline in this session. Each task starts with a failing test (RED), then the smallest production change to make it pass (GREEN). Keep the working tree clean between tasks except for intentional staged progress.

## Task 1: Reject zero ring size

Files: `src/core/watch.rs`, `tests/core_tests.rs`.

1. Add a unit test in `src/core/watch.rs` asserting that `watch` with `ring_lines: 0` returns an error mentioning `ring_lines`.
2. Add a CLI integration test asserting `logcut watch --ring-lines 0 -- sh -c 'echo ok'` fails with a non-zero status and the same diagnostic on stderr.
3. Run the new tests and confirm RED: `cargo test --lib core::watch::tests::zero_ring_lines_bails` and `cargo test --test core_tests cli_watch_rejects_zero_ring_lines`.
4. In `watch()`, before spawning the child, `bail!` when `request.ring_lines == 0`; remove the silent `500` fallback and use `request.ring_lines` directly.
5. GREEN: run both new tests and then `cargo test --lib core::watch`.

## Task 2: Include `warning` in the invalid `min_level` diagnostic

Files: `src/core/json_log.rs`.

1. Change the existing `unknown_min_level_is_rejected` test to also assert the message mentions `warning` alongside the accepted levels.
2. Run `cargo test --lib core::json_log::tests::unknown_min_level_is_rejected` and confirm RED.
3. Update the `bail!` message in `validate()` to list `trace, debug, info, warn, warning, error, or fatal`.
4. GREEN: run the unit test and `cargo test --all-features`.

## Task 3: Do not read stdin when `logcut test --raw-text` is used

Files: `src/main.rs`, `tests/core_tests.rs`.

1. Add an integration test that spawns `logcut test --raw-text ...` with a piped stdin that is deliberately left open, polls with `try_wait`, kills the child if it has not exited within a few seconds, and asserts the report contains the injected failure.
2. Run `cargo test --test core_tests cli_test_raw_text_ignores_piped_stdin` and confirm RED (the child blocks reading stdin).
3. In `Commands::Test`, mirror `Commands::Slice`: read piped stdin only when `args.file.is_none() && args.raw_text.is_none() && !io::stdin().is_terminal()`.
4. GREEN: run the new test and the existing `cli_test_prints_only_failures` test.

## Task 4: Documentation consistency

Files: `docs/usage.md`, `docs/architecture.md`.

1. `docs/usage.md`: state that `--ring-lines 0` is rejected; document that `where` values compare case-sensitively (so bare `level=error` only matches lowercase stored values, while `min_level` is case-insensitive); note that watched child output with invalid UTF-8 is decoded lossily rather than aborting the report.
2. `docs/architecture.md`: make the watch data-flow sentence match the actual detector (crash markers, severity-shaped `ERROR`/`FATAL`, or non-zero exit) and note that zero ring size is rejected at the core boundary.
3. No test is required for prose; verify with `git diff --check` and a human read-through of the rendered Markdown.
