## Task 1 — Strict `min_level` and `where_filters` validation in core

Files: `src/core/json_log.rs`, `src/core/mod.rs`, `tests/core_tests.rs` (only if an integration-level assertion is useful).

1. In `src/core/json_log.rs`, add `use anyhow::{Result, bail};` and a strict private parser:

   ```rust
   fn parse_level(level: &str) -> Option<u8>
   ```

   It accepts trimmed ASCII-lowercase `trace|debug|info|warn|warning|error|fatal` (the existing `warning` alias must stay valid so `severity("WARNING") == 3` continues to pass) and returns `None` otherwise. Rewrite `severity()` to call `parse_level(...).unwrap_or(2)` so untrusted log levels keep defaulting to INFO.

2. Add the RED tests in `json_log::tests` first:

   ```rust
   #[test]
   fn unknown_min_level_is_rejected() {
       let err = slice("{\"level\":\"info\",\"message\":\"x\"}", Some("loud"), &[]).unwrap_err();
       assert!(err.to_string().contains("loud"), "{err:#}");
   }

   #[test]
   fn malformed_where_filters_are_rejected() {
       for filter in ["status", "=auth", "status=", "   ", "status>= "] {
           let err = slice("{\"level\":\"info\",\"message\":\"x\"}", None, &[filter.to_owned()]).unwrap_err();
           assert!(err.to_string().contains(filter), "{err:#}");
       }
   }
   ```

   Run `cargo test --lib core::json_log::tests::unknown_min_level_is_rejected` and `...::malformed_where_filters_are_rejected`; both must fail to compile because `slice` returns `Vec`. That is the expected RED state.

3. Change the signature to:

   ```rust
   pub fn slice(text: &str, min_level: Option<&str>, where_filters: &[String]) -> Result<Vec<JsonLogEntry>>
   ```

   Before parsing any line: reject a `min_level` for which `parse_level` returns `None` with `bail!("invalid min_level {:?}; expected trace, debug, info, warn, error, or fatal", value)`; reject any filter for which `parse_filter` returns `None` with `bail!("invalid where filter {:?}; expected field=value, field!=value, field>value, field>=value, field<value, or field<=value", filter)`.

4. Tighten `parse_filter` so the value must be non-empty as well as the field (`if !field.is_empty() && !value.is_empty()`). Pre-parse the validated filters into `Vec<(&str, Operator, &str)>` and change `matches_filter` to take those parts instead of re-parsing a raw string. This removes the `parse_filter` failure branch that previously meant “match everything”. Keep numeric comparison and absent-field behavior unchanged.

5. Append `.unwrap()` to every existing `slice(...)` call in `json_log::tests`, and add `?` to the call in `src/core/mod.rs:38` so `slice_log` propagates validation errors to both CLI and MCP.

6. GREEN check: run `cargo test --lib core::json_log`, then `cargo test --all-features`. Confirm no silent-acceptance tests remain by grepping for `slice(` calls without `unwrap`/`?`.

## Task 2 — Atomic writes for both `.logcut` files

Files: `src/core/watch.rs`.

1. Add a RED unit test that calls the extracted helper directly:

   ```rust
   #[test]
   fn atomic_writer_leaves_no_temp_files() {
       let dir = tempfile::tempdir().unwrap();
       let destination = dir.path().join(".gitignore");
       write_file_atomically(&destination, "*").unwrap();
       assert_eq!(std::fs::read_to_string(&destination).unwrap(), "*");
       let entries = std::fs::read_dir(dir.path()).unwrap().count();
       assert_eq!(entries, 1, "unexpected files in {:?}", dir.path());
   }
   ```

   Run `cargo test --lib core::watch::tests::atomic_writer_leaves_no_temp_files`; it must fail because the helper does not exist yet.

2. Replace `write_atomically(workspace_root, destination, text)` with:

   - `fn logcut_dir(workspace_root: &str) -> Result<PathBuf>` — `create_dir_all(root/.logcut)` and return the path.
   - `fn write_file_atomically(destination: &Path, text: &str) -> Result<()>` — the existing temp-file + `write_all` + `flush` + `sync_all` + `rename` + cleanup-on-error body, with the temp name derived from `destination.file_name()` (e.g. `.gitignore.tmp-<pid>-<seq>`).

3. In `watch()`'s crash branch, call `logcut_dir`, then `write_file_atomically(&dir.join(".gitignore"), "*")`, then `write_file_atomically(&path, &sliced.text)`. The existing `non_zero_exit_and_error_line_writes_report` test already asserts both file contents; keep it green.

4. GREEN check: run `cargo test --lib core::watch`, then `cargo test --all-features`.
